Manage native PAM authentication, passwd/group NSS providers, login access rules
and domain home labels.

## Purpose

Own the system PAM stack and passwd/group NSS provider selection through native
distribution tools.

## Scope

### Managed

- Native authentication packages and provider selection for sssd, winbind or
  local accounts.
- PAM home creation, ordered pam_access login rules and passwd/group NSS
  provider sources.
- SELinux home-root equivalence mappings and relabeling of existing homes under
  changed roots.

### Not Managed

- sssd.conf, pam_winbind.conf, smb.conf, krb5.conf, keytabs and domain joins.
- Direct edits under /etc/pam.d, sshd configuration, additional NSS database
  policies and package removal.
- Provider daemon configuration and lifecycle, optional authentication hardware
  or module enrollment.

## Requirements

- Select pam_provider explicitly. For AD members, run jomrr.krb5, then
  jomrr.pam, then jomrr.samba_ad_sssd or jomrr.samba_ad_member.
- The provider role configures and starts SSSD or winbind after this role
  selects its PAM and NSS integration.
- Red Hat hosts need a native authselect profile for the selected provider.
  pam_authselect_force explicitly permits adoption of unmanaged PAM/NSS files.
- Applications must use the native PAM stack; SSH authentication settings remain
  the responsibility of the sshd configuration.

## Dependencies

```yaml
collections:
  - name: community.general
    version: '>=12.0.0'
```

## Role Variables

### `pam_provider`

Type: `str`. Required: `true`.

Identity provider selected in the native PAM and NSS configuration.

### `pam_mkhomedir`

Type: `bool`. Required: `false`.

Create home directories through the native PAM session module.

Default:

```yaml
pam_mkhomedir: true
```

### `pam_authselect_features`

Type: `list`. Required: `false`.

Additional Red Hat profile features; home creation and access rules are
controlled separately.

Default:

```yaml
pam_authselect_features:
  - without-nullok
  - with-faillock
```

### `pam_authselect_force`

Type: `bool`. Required: `false`.

Allow authselect to adopt unmanaged PAM/NSS files with its native backup
mechanism.

Default:

```yaml
pam_authselect_force: false
```

### `pam_access_rules`

Type: `list`. Required: `false`.

Ordered pam_access rules; an empty list disables the module and preserves
access.conf.

Default:

```yaml
pam_access_rules: []
```

### `pam_home_roots`

Type: `list`. Required: `false`.

Absolute home roots below /home for SELinux equivalence mappings; removed
entries are not cleaned up.

Default:

```yaml
pam_home_roots: []
```

## Managed Files

- `/etc/security/access.conf (root:root, mode 0644; managed only when
  pam_access_rules is nonempty)`
- `/usr/share/pam-configs/access (Debian only; deactivated before removal when
  no access rules are configured)`
- `/etc/nsswitch.conf (passwd/group sources on Debian and openSUSE; exclusively
  generated by authselect on Red Hat)`
- `Platform PAM configuration generated exclusively by authselect,
  pam-auth-update or pam-config`
- `SELinux file-context equivalence rules for pam_home_roots`

## Check Mode

Supported on an already prepared host; native state reads also run in check
mode.

- A first check run cannot install native tools. Converge a fresh host before
  checking it.

## Service Behavior

On Red Hat, pam_mkhomedir=true enables and starts oddjobd. With false, its state
remains unchanged.

### Handlers

- relabel home roots

## Security Notes

- Red Hat defaults enable without-nullok and with-faillock. Lockout thresholds
  follow distribution defaults and /etc/security/faillock.conf, which this role
  does not manage.
- pam_access rules apply to all accounts, including root and local users. The
  first matching rule decides. No implicit allow or deny rule is added.
- Write group names in parentheses. Names must not contain spaces, because
  pam_access separates field elements on whitespace.

## Operational Notes

- Each pam_home_roots entry is the parent of user homes. For
  /home/EXAMPLE/alice, use /home/EXAMPLE. SELinux then evaluates
  /home/EXAMPLE/alice/.ssh like /home/alice/.ssh, including the specific
  ssh_home_t policy.
- pam_provider is required. pam_mkhomedir defaults to true; pam_access_rules and
  pam_home_roots default to empty lists. Changing providers does not remove
  packages or stop provider daemons.
- All authentication packages are installed before reading native selection.
  Debian libpam-sss and libpam-winbind post-install scripts may already activate
  their profiles.
- On Red Hat, the desired authselect selection consists of the provider plus
  pam_authselect_features. with-mkhomedir and with-pamaccess in that list are
  ignored: pam_mkhomedir and nonempty pam_access_rules control them. Changes run
  authselect select only when the sorted current selection differs.
- Available authselect features are profile-specific; for example with-krb5
  belongs to winbind. The native tool rejects unsupported features. Use
  authselect list-features and authselect requirements for the chosen profile.
  Optional module packages and enrollment remain separately provisioned.
- Replacing pam_authselect_features replaces its defaults. Include
  without-nullok and with-faillock when retaining those policies. An empty list
  disables those additional features. The variable does not configure Debian or
  openSUSE.
- On Debian, the role changes only the sss, winbind, mkhomedir and access
  profiles in one pam-auth-update invocation when necessary. unix, systemd and
  foreign profiles keep their selection.
- The Debian access profile uses priority 1024 to run before provider profiles.
  This prevents SSSD's sufficient pam_localuser account check from bypassing
  access rules for local users. A changed profile definition also regenerates
  the native stack.
- On openSUSE, pam-config queries and changes sss, winbind, mkhomedir and access
  individually. Missing /etc/nsswitch.conf is initialized from
  /usr/etc/nsswitch.conf without overwriting an existing file.
- Debian and openSUSE keep existing passwd/group sources, their order and
  comments. The selected provider source is appended only when missing; the
  other provider is removed. local removes both sss and winbind. Other NSS lines
  are untouched.
- On Red Hat, /etc/nsswitch.conf belongs entirely to authselect. This role never
  edits its symlink or real target directly; profile regeneration must remain
  authoritative.
- An empty pam_access_rules list deactivates pam_access and leaves access.conf
  untouched. On Debian, its native profile file is removed only after profile
  deactivation. The role manages access.conf as a complete file when rules are
  present.
- genhomedircon assumes /home as its home root. Nested domain homes otherwise
  receive user_home_t where their directory needs user_home_dir_t. On
  SELinux-enabled hosts, pam_home_roots adds equivalence mappings from each
  absolute root below /home to /home.
- A changed home-root mapping notifies recursive restorecon for that root.
  Nonexistent roots are ignored until homes exist. Removed pam_home_roots
  entries are not cleaned up; manage removal explicitly outside the role.
- There is no standalone candidate-file validator for access.conf. Its ordered
  behavior is tested through native PAM account checks; generated stacks use
  native configuration tools.

## Example Playbook

### SSSD domain member

Select native authentication before configuring the domain provider.

```yaml
---
- name: Configure domain logins
  hosts: workstations
  gather_facts: true
  roles:
    - role: jomrr.krb5
      krb5_realm: AD.EXAMPLE.COM
    - role: jomrr.pam
      pam_provider: sssd
      pam_home_roots:
        - /home/ad.example.com
    - role: jomrr.samba_ad_sssd
      samba_ad_sssd_realm: AD.EXAMPLE.COM
      samba_ad_sssd_join_password: "{{ vault_ad_join_password }}"
```

### Winbind member

Samba owns pam_winbind.conf; the pam role owns the native stack and NSS.

```yaml
---
- name: Configure a Samba member
  hosts: fileservers
  gather_facts: true
  roles:
    - role: jomrr.krb5
      krb5_realm: AD.EXAMPLE.COM
    - role: jomrr.pam
      pam_provider: winbind
      pam_home_roots:
        - /home/EXAMPLE
    - role: jomrr.samba_ad_member
      samba_ad_member_realm: AD.EXAMPLE.COM
      samba_ad_member_domain: EXAMPLE
      samba_ad_member_server: dc1.ad.example.com
      samba_ad_member_join_password: "{{ vault_ad_join_password }}"
```

### Local provider with explicit login access

Allow the administrative group before an explicit deny rule.

```yaml
---
- name: Configure local logins
  hosts: standalone
  gather_facts: true
  roles:
    - role: jomrr.pam
      pam_provider: local
      pam_mkhomedir: false
      pam_access_rules:
        - permission: '+'
          users: [root, '(administrators)']
          origins: [ALL]
        - permission: '-'
          users: [ALL]
          origins: [ALL]
```
