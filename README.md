Manage native PAM authentication, passwd/group NSS providers and domain home
labels.

## Purpose

Own the system PAM stack and passwd/group NSS provider selection through native
distribution tools.

## Scope

### Managed

- Native authentication packages and provider selection for sssd, winbind or
  local accounts.
- PAM home creation and passwd/group NSS provider sources.
- Optional group restrictions for domain accounts in the system PAM account
  phase, including GSSAPI logins.
- SELinux home-root equivalence mappings and relabeling of existing homes under
  changed roots.

### Not Managed

- sssd.conf, pam_winbind.conf, smb.conf, krb5.conf, keytabs and domain joins.
- Winbind packages and daemon configuration; these belong to the Samba role.
- sshd configuration, independent service PAM stacks, additional NSS database
  policies and package removal.
- Provider daemon configuration and lifecycle, optional authentication hardware
  or module enrollment.

## Requirements

- Select pam_provider explicitly for standalone use. jomrr.sssd and
  jomrr.samba_ad_member invoke this role internally after jomrr.krb5, selecting
  sssd and winbind respectively.
- Provider daemon configuration and startup belong to the calling SSSD or Samba
  role. With pam_provider=winbind, its PAM and NSS modules must already be
  installed by the Samba role.
- Red Hat hosts need a native authselect profile for the selected provider.
  pam_authselect_force explicitly permits adoption of unmanaged PAM/NSS files.
- Applications must use the native PAM stack; SSH authentication settings remain
  the responsibility of the sshd configuration.

## Dependencies

```yaml
collections:
  - name: community.general
    version: '>=12.0.0'
```

## Role Variables

### `pam_provider`

Type: `str`. Required: `true`.

Identity provider selected in the native PAM and NSS configuration.

### `pam_mkhomedir`

Type: `bool`. Required: `false`.

Create home directories through the native PAM session module.

Default:

```yaml
pam_mkhomedir: true
```

### `pam_access_groups`

Type: `list`. Required: `false`.

NSS group names allowed for domain users in the system PAM account phase. Local
passwd accounts are exempt; an empty list disables this restriction. Requires
the sssd or winbind provider.

Default:

```yaml
pam_access_groups: []
```

### `pam_backup`

Type: `bool`. Required: `false`.

Back up managed configuration files before replacing them.

Default:

```yaml
pam_backup: true
```

### `pam_authselect_features`

Type: `list`. Required: `false`.

Additional Red Hat profile features; home creation is controlled separately.

Default:

```yaml
pam_authselect_features:
  - without-nullok
  - with-faillock
```

### `pam_authselect_force`

Type: `bool`. Required: `false`.

Allow authselect to adopt unmanaged PAM/NSS files with its native backup
mechanism.

Default:

```yaml
pam_authselect_force: false
```

### `pam_home_roots`

Type: `list`. Required: `false`.

Absolute home roots below /home for SELinux equivalence mappings; removed
entries are not cleaned up.

Default:

```yaml
pam_home_roots: []
```

## Managed Files

- `/etc/nsswitch.conf (passwd/group sources on Debian and openSUSE; exclusively
  generated by authselect on Red Hat)`
- `Platform PAM configuration selected through authselect, pam-auth-update or
  pam-config`
- `/etc/pam.d/pam-access and /etc/security/pam-access.conf`
- `Native account authorization profile sources`
- `On openSUSE with pam-config before 2.14, /etc/pam.d/common-account and
  /etc/pam.d/pam-access-common-account while group restrictions are active`
- `SELinux file-context equivalence rules for pam_home_roots`

## Check Mode

Supported on an already prepared host; native state reads also run in check
mode.

- A first check run cannot install native tools. Converge a fresh host before
  checking it.

## Service Behavior

On Red Hat, pam_mkhomedir=true enables and starts oddjobd. With false, its state
remains unchanged.

### Handlers

- relabel home roots

## Security Notes

- Red Hat defaults enable without-nullok and with-faillock. Lockout thresholds
  follow distribution defaults and /etc/security/faillock.conf, which this role
  does not manage.
- pam_access_groups adds a required account check, so passwordless
  authentication still requires group membership. Local accounts are identified
  from /etc/passwd at login time. Services must call the system account stack.
  OpenSSH needs UsePAM=yes.
- On openSUSE, pam-config 2.14 and later orders pam_access after the native
  local-user exemption and before the domain provider. Earlier versions run the
  dedicated group check as a PAM substack, then include SUSE's generated
  common-account-pc. Both use /etc/security/pam-access.conf. NSS caches can
  delay group changes, particularly offline.

## Operational Notes

- Each pam_home_roots entry is the parent of user homes. For
  /home/EXAMPLE/alice, use /home/EXAMPLE. SELinux then evaluates
  /home/EXAMPLE/alice/.ssh like /home/alice/.ssh, including the specific
  ssh_home_t policy.
- pam_provider is required. pam_mkhomedir defaults to true; pam_home_roots
  defaults to an empty list. Changing providers does not remove packages or stop
  provider daemons.
- All authentication packages are installed before reading native selection.
  Debian libpam-sss and libpam-winbind post-install scripts may already activate
  their profiles.
- On Red Hat, the desired authselect selection consists of the provider plus
  pam_authselect_features. With pam_access_groups, the role derives a custom
  profile from the installed provider profile and inserts account authorization
  before sufficient modules. with-mkhomedir in that list is ignored:
  pam_mkhomedir controls home creation. Changes run authselect select only when
  the sorted current selection differs.
- Available authselect features are profile-specific; for example with-krb5
  belongs to winbind. The native tool rejects unsupported features. Use
  authselect list-features and authselect requirements for the chosen profile.
  Optional module packages and enrollment remain separately provisioned.
- Replacing pam_authselect_features replaces its defaults. Include
  without-nullok and with-faillock when retaining those policies. An empty list
  disables those additional features. The variable does not configure Debian or
  openSUSE.
- On Debian, the role selects sss, winbind, mkhomedir and its pam-access profile
  in one pam-auth-update invocation when necessary. unix, systemd and foreign
  profiles keep their selection.
- On openSUSE, pam-config queries and changes sss, winbind and mkhomedir
  individually. Missing /etc/nsswitch.conf is initialized from
  /usr/etc/nsswitch.conf without overwriting an existing file.
- On openSUSE the role accepts the distribution's common-account symlink or its
  own when enabling group restrictions. Resolve a locally managed entry before
  enabling them. With pam-config before 2.14, ordinary updates refresh the
  included common-account-pc. Reapply the role after forcing or reinitializing
  the PAM configuration. Disabling the restriction restores the distribution
  link. After upgrading pam-config, the role activates and verifies the native
  rule before restoring that link.
- pam_access_groups accepts NSS group names, including spaces. At least one
  group must match. The native PAM stack and provider must resolve domain
  membership. SIDs are resolved by the calling identity-provider role. Local
  accounts in /etc/passwd, including root, remain exempt; [] disables this
  account restriction.
- Debian and openSUSE keep existing passwd/group sources, their order and
  comments. The selected provider source is appended only when missing; the
  other provider is removed. local removes both sss and winbind. Other NSS lines
  are untouched.
- On Red Hat, /etc/nsswitch.conf belongs entirely to authselect. This role never
  edits its symlink or real target directly; profile regeneration must remain
  authoritative.
- genhomedircon assumes /home as its home root. Nested domain homes otherwise
  receive user_home_t where their directory needs user_home_dir_t. On
  SELinux-enabled hosts, pam_home_roots adds equivalence mappings from each
  absolute root below /home to /home.
- A changed home-root mapping notifies recursive restorecon for that root.
  Nonexistent roots are ignored until homes exist. Removed pam_home_roots
  entries are not cleaned up; manage removal explicitly outside the role.

## Example Playbook

### SSSD domain member

SSSD selects native authentication internally; pam options remain configurable.

```yaml
---
- name: Configure domain logins
  hosts: workstations
  gather_facts: true
  roles:
    - role: jomrr.sssd
      pam_home_roots:
        - /home/ad.example.com
      sssd_realm: AD.EXAMPLE.COM
      sssd_join_password: "{{ vault_ad_join_password }}"
```

### Winbind member

Samba owns Winbind packages and pam_winbind.conf and passes resolved
login groups to this role.

```yaml
---
- name: Configure a Samba member
  hosts: fileservers
  gather_facts: true
  roles:
    - role: jomrr.samba_ad_member
      pam_home_roots:
        - /home/EXAMPLE
      samba_ad_member_realm: AD.EXAMPLE.COM
      samba_ad_member_domain: EXAMPLE
      samba_ad_member_server: dc1.ad.example.com
      samba_ad_member_join_password: "{{ vault_ad_join_password }}"
```

### Local provider without home creation

Select local authentication with automatic home creation disabled.

```yaml
---
- name: Configure local logins
  hosts: standalone
  gather_facts: true
  roles:
    - role: jomrr.pam
      pam_provider: local
      pam_mkhomedir: false
```
